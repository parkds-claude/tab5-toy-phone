## 한눈에 보기 (사용자용)

전화가 왔을 때 할 수 있는 일이 두 가지 늘어난다. 받기·거절 버튼은 지금 자리·크기 그대로다.

```
[받는 쪽] 벨 화면                              [받는 쪽] 메시지 고르기 화면

        전화가 왔습니다                          보낼 메시지를 누르면 거절됩니다

  [   받기   ]    [   거절   ]             [회의 중이에요] [지금은 받을 수 없어요] [잠시 후 다시 걸게요]

  [ 벨 끄기  ]    [메시지로 거절]  ← 새 버튼                 (가운데는 비워 둔다)

                                           [  뒤로  ]

[거는 쪽] 거절당한 뒤의 대기 화면:  위쪽 안내 상자에  "상대: 회의 중이에요"  (10초 동안)
```

- **벨 끄기** — 이번 전화의 벨만 끈다. 버튼 글자가 "벨 꺼짐"으로 바뀌고(다시 눌러도 다시 켜지지 않는다), 화면은 그대로라 이어서 받거나 거절할 수 있다. 건 사람은 모른다. 다음 전화는 다시 울린다.
- **메시지로 거절** — 누르면 고르기 화면으로 넘어간다. 문구를 누르는 순간 거절되고, 건 사람 화면에 그 문구가 10초 동안 뜬다. 마음이 바뀌면 "뒤로"를 눌러 벨 화면으로 돌아가 받을 수 있다. 고르는 동안 상대가 끊거나 30초가 지나면 지금처럼 부재중 1건이 된다.
- 문구 버튼이 화면 **위쪽**에 있는 이유: 고르는 사이 상대가 끊으면 화면이 대기 화면으로 바뀌는데, 그 순간 손가락이 가운데의 통화 버튼을 눌러 되거는 일이 없게 하려는 것이다(DM-D3).
- **아직 안 되는 것**: 실제 벨소리는 Phase 3(소리)에서 생긴다. 지금은 버튼·화면·내부 동작까지 만들고, 소리가 정말 꺼지는지는 Phase 3 에서 확인한다.
- **사용자가 할 일**: 화면 사진을 보고 모양·색 의견 주기 → 직접 눌러 보기(Phase 2 계획 Task 9 에 합쳐 한 번에) → §11 의 확인 질문 3개(답이 없으면 제안대로 진행).

## 1. 목표 (Goal)

받는 쪽 벨 화면에서 ① **벨 끄기**를 누르면 그 통화의 벨만 멈추고(신호는 나가지 않는다) ② **메시지로 거절** → 문구 1·2·3 중 하나를 누르면 통화가 거절되면서 거는 쪽 대기 화면에 "상대: <문구>"가 10초간 뜬다. 번호가 없는 거절과 그 밖의 통화 흐름은 지금과 똑같이 동작한다(기존 시험을 고치지 않고 전부 통과). 완료 판정은 §8.

## 5. 설계

### 5.1 사용 흐름

**받는 쪽**
1. 전화가 오면 벨 화면: 제목 + 받기·거절(그대로) + 아래 줄에 **벨 끄기**(왼쪽)·**메시지로 거절**(오른쪽).
2. 벨 끄기 → 그 자리가 "벨 꺼짐"(흐린 글자, 더는 버튼이 아니다)으로 바뀐다. 통화 상태·30초 제한·다른 버튼은 그대로이고 신호는 나가지 않는다.
3. 메시지로 거절 → 메시지 고르기 화면: 위에 안내 문구, 그 아래 한 줄에 문구 버튼 셋, 아래 왼쪽에 뒤로. 통화 상태는 벨 그대로다(벨 제한·상대 취소가 그대로 돈다). 열어도 벨은 계속 울린다(끄려면 먼저 벨 끄기).
4. 문구를 누르면 → "끊는 중…" → 대기. 안내·부재중 없음(지금의 거절과 같다). 뒤로를 누르면 → 벨 화면.
5. 고르는 중에 상대가 끊거나 30초가 지나거나 교환기가 끊기면 → 고르기 화면이 닫히고 지금처럼 부재중 1건.

**거는 쪽**: 문구와 함께 거절되면 대기 화면으로 돌아오면서 위쪽 안내 상자에 "상대: <문구>"가 **10초** 뜬다(지금의 "상대가 받지 않고 끊었어요" 자리. 그 밖의 안내는 4초 그대로). 그냥 거절이면 지금 문구 그대로다.

### 5.2 신호 규약 변경 (설계서 §9.4 에 더한다)

| 방향 | 글자 프레임 | 뜻 |
|---|---|---|
| 기기 → 교환기 | `{"t":"reject"}` (그대로) · `{"t":"reject","msg":N}` (**신규**, N = 1~3) | 그냥 거절 · 문구 N 과 함께 거절 |
| 교환기 → 양쪽 | `{"t":"ended","why":"reject"}` (그대로) · `{"t":"ended","why":"reject","msg":N}` (**신규**) | 거절로 끝남 · 문구 N 과 함께 거절로 끝남 |

- **교환기**(`phone_core.py`): `msg` 는 `reject` 에서만 읽는다. 값이 정수(참·거짓 제외)이고 `REJECT_MSG_MIN = 1` ~ `REJECT_MSG_MAX = 99` 일 때만 `ended` 에 그대로 싣는다. 그 밖(0·음수·100 이상·소수·글자·참거짓·null·배열·객체)은 **번호 없는 거절**로 처리한다(통화는 끝난다, `bad_signal` 은 올리지 않는다). 교환기는 번호의 뜻을 모른다. `reject` 가 유효한 조건(벨 중 + 받는 쪽)은 그대로다. `call_end` 기록에 `msg` 를 넣지 않는다(설계서 §9.3 "기록: 시각·기기·통화 길이·종료 사유만"). 구현 자리는 `_end(why, now, msg=None)` 의 선택 인자와 새 도우미 `_reject_msg(msg)` — 다른 종료(`hangup`·`timeout`·`offline`·`lost`)의 `ended` 는 글자 하나 달라지지 않는다.
- **기기가 읽을 때**(`relay_proto.h` `parse`): `"msg"` 는 `"n"` 과 같은 숫자 가지에서 읽는다. **숫자만으로 된 1~`MSG_COUNT`(3)** 이고 `t=ended`·`why=reject` 일 때만 `Signal.msg` 에 담고, 그 밖은 0. 비교는 64비트 값 그대로 한다 — 32비트로 잘라 비교하면 4294967297(2^32+1)이 1 로 읽힌다.
- **기기가 보낼 때**: `inline int reject_text(char *buf, size_t cap, uint8_t msg)` — 번호가 1~3 이면 `{"t":"reject","msg":N}`, 아니면 `{"t":"reject"}` 를 쓴다(`ping_text` 와 같은 계약: 글자 수, 안 들어가면 0). `text_for(A_SEND_REJECT)` 는 그대로 둔다.
- 가장 긴 새 프레임은 37바이트(`{"t":"ended","why":"reject","msg":99}`)로 양쪽 상한 256바이트에 한참 못 미친다.

### 5.3 통화 상태 기계 변경 (`call_fsm.h`)

```cpp
const uint8_t MSG_COUNT = 3;                                            // 문구 번호는 1~MSG_COUNT, 0 = 없음
inline bool msg_valid(uint64_t n) { return n >= 1 && n <= MSG_COUNT; }
struct Out { uint16_t acts = 0; Notice notice = Notice::NONE; uint8_t msg = 0; };
Out on(Ev ev, int64_t now_ms, Why why = Why::NONE, bool flag = false, uint8_t msg = 0);
```

새 사건은 `Ev::TAP_MUTE` 하나, 새 안내는 `Notice::REJECT_MSG`(이름 `"REJECT_MSG"`), 새 기억은 `Fsm::bell_muted` 다. 메시지 거절은 새 사건이 아니라 기존 `TAP_REJECT` 에 번호를 실어 넣는다(DM-D7).

| 상태 | 사건(조건) | 다음 상태 | 할 일 `acts` | `Out.msg` | 안내 |
|---|---|---|---|---|---|
| INCOMING | `TAP_MUTE` (처음) | INCOMING — 시간 제한도 그대로 | `A_TONE_STOP` (0x80) | 0 | 없음. `bell_muted = true` |
| INCOMING | `TAP_MUTE` (이미 꺼짐) | 그대로 | 0 | 0 | 없음 |
| INCOMING | `TAP_REJECT`, 번호 1~3 | ENDING(3초) | `A_SEND_REJECT\|A_TONE_STOP` (0x84) | 번호 | 없음 |
| INCOMING | `TAP_REJECT`, 번호 0·범위 밖 | ENDING(3초) | 0x84 | 0 | 없음 — 지금과 같다 |
| DIALING·RINGBACK | `ENDED` why=reject, 번호 1~3 | IDLE | `A_TONE_END` (0x40) | 번호 | `REJECT_MSG` |

- `bell_muted` 는 `enter()` 와 `offline()` 이 지운다 → 받기·거절·부재중·연결 끊김·시간 제한 등 INCOMING 을 떠나는 모든 길에서 풀리고, 다음 전화는 꺼지지 않은 상태로 시작한다.
- **Phase 3(소리)로 넘기는 약속**: 상태 기계는 `A_TONE_BELL` 을 `IDLE → INCOMING` 으로 들어갈 때 **한 번만** 낸다(INCOMING 안에서 온 `RING` 은 아무 할 일도 내지 않는다 — 지금 코드가 그렇고, 시험으로 고정한다). 그래서 벨 끄기의 `A_TONE_STOP` 뒤에는 그 통화가 끝날 때까지 벨을 다시 시작시키는 할 일이 나오지 않는다. 소리 모듈은 ① `A_TONE_STOP` 을 받으면 반복을 멈추고 스스로 다시 시작하지 않는다 ② 이미 멈춘 상태에서 `A_TONE_STOP` 이 또 와도(받기·거절·부재중 때 한 번 더 온다) 탈이 없어야 한다.

**시험으로 고정하는 겹침 규칙** (계획 PL2-D5 "시간 가드 + 버튼 배치 두 겹"의 배치 쪽. 제안 좌표를 저장소의 기존 상수와 함께 계산해 전부 통과함을 확인했다)
1. `BTN_DECLINE` 은 고르기 화면의 문구 셋·뒤로와 겹치지 않는다 — "메시지로 거절"을 누른 터치가 또 잡혀도 빈 자리에 떨어진다.
2. 문구 셋은 통화 쪽 화면의 **어떤 버튼과도** 겹치지 않는다(대기·부팅 화면의 통화 원·Wi-Fi 배지, 벨 화면의 네 버튼, 취소, 끊기) — 고르는 중 화면이 바뀌어도, 문구를 누른 터치가 또 잡혀도 아무것도 눌리지 않는다. 문구 줄 아래(y 232)는 통화 원 꼭대기(y 240)보다 8px 위다.
3. `BTN_BACK` 은 벨 화면의 받기·거절·메시지로 거절과 겹치지 않는다.
4. 기존 규칙(받기·거절 ↔ 끊기, 통화 ↔ 취소·끊기)은 상수를 건드리지 않으므로 그대로다. 같은 화면 안의 버튼끼리도 겹치지 않고(벨 끄기 ↔ 메시지로 거절 112px), 새 버튼은 모두 96px 이상·8px 격자·화면 안이다.

**남는 겹침과 판정** (새 버튼 × 통화 쪽 다른 화면의 버튼, 계산으로 뽑은 전부)

| 새 버튼 | 겹치는 버튼(화면) | 겹치는 곳 | 한 번의 터치로 닿는 길 | 판정 |

### 5.6 그리기·진행·시리얼 규약

**`ui.cpp`**
- `draw_incoming(m)`: 기존 제목·받기·거절에 `BTN_MUTE`(`bell_muted` 면 `lbl_mute_done` + `C_MUTED`)와 `BTN_DECLINE` 을 더한다. "벨 꺼짐"에 `gfx::button(…, enabled=false, …)` 는 쓰지 않는다 — 그 모양은 글자가 `C_LINE` 이라 거의 보이지 않는다.
- `draw_decline(m)`(신규): 안내 문구 + `BTN_MSG[i]` 셋 + `BTN_BACK`. `ui::draw()` 의 `switch` 에 `Screen::DECLINE` 을 더한다.
- 안내 상자: `REJECT_MSG` 면 `MSG_NOTICE[m.notice_msg - 1]`(범위 밖이면 `lbl_n_rejected`). `notice_visible(m)` 일 때만 그린다.
- `MSG_LABEL[]`·`MSG_NOTICE[]` 는 크기를 적지 않은 배열로 두고 `static_assert` 로 개수가 `callfsm::MSG_COUNT` 와 같음을 묶는다(문구 수가 어긋나면 빌드가 실패한다).

**`app.cpp`**
- `feed(ev, now, why, flag, msg)`: `s_fsm.on(…, msg)` 뒤에 **사건마다** `s_picker.sync(s_fsm.state)` 를 부른다. `refresh()` 에서만 맞추면 한 바퀴 안에 `ended` → `ring` 이 연달아 올 때 다음 전화가 고르기 화면으로 뜬다. `app_task` 는 `in.sig.msg` 를 넘긴다.
- `on_tap()`: `MUTE` → `feed(Ev::TAP_MUTE)` / `DECLINE_OPEN`·`DECLINE_BACK` → `s_picker.on_tap(t)`(상태 기계에는 넣지 않는다) / `MSG1~3` → `feed(Ev::TAP_REJECT, now, Why::NONE, false, uilayout::msg_of(t))`.
- `apply()`: `A_SEND_REJECT` 는 `relayproto::reject_text(buf, …, o.msg)` 로 만든 글자를 보낸다(`send_text` 는 호출 안에서 다 보내므로 스택 버퍼로 충분하다 — ping 과 같은 방식). 안내를 받으면 `s_notice_msg = o.msg`, 끝 시각 = `now + uilayout::notice_ms(o.notice)`. `NOTICE_MS` 상수는 `ui_layout.h` 로 옮긴다(DM-D10).
- `refresh()`: `Model` 의 새 세 칸을 채운다. **`same()` 에 세 칸 비교를 더한다** — 빠뜨리면 눌러도 화면이 다시 그려지지 않는다.
- 고르기 화면이 열리고 닫히면 화면 이름이 바뀌므로 지금의 600ms 화면 가드가 그대로 걸린다(연 직후 0.6초는 문구를, 뒤로 직후 0.6초는 받기·거절을 받지 않는다).

**시리얼 규약** (기존 줄의 모양은 그대로이고 뒤에만 덧붙는다. `STAT` 줄과 명령 `stat`·`t`·`shot`·`reboot` 는 변화 없음)

| 줄 | 추가되는 것 |
|---|---|
| `SCREEN <이름>` | `DECLINE`. 통화 상태는 그대로라 `STAT … fsm=INCOMING … screen=DECLINE` 으로 보인다 |
| `FSM … notice=<이름>` | 안내 이름 `REJECT_MSG`. 번호가 있을 때만 줄 끝에 ` msg=<1~3>` |
| 예 | `FSM INCOMING -> INCOMING acts=0x80 notice=NONE`(벨 끄기) · `FSM INCOMING -> ENDING acts=0x84 notice=NONE msg=2`(메시지 거절) · `FSM RINGBACK -> IDLE acts=0x40 notice=REJECT_MSG msg=2`(거는 쪽) |

기존 정규식 `notice=REJECTED` 는 새 안내에 걸리지 않는다(`REJECT_MSG` 는 `REJECTED` 로 시작하지 않는다 — DM-D9). 그냥 거절임을 엄격히 볼 때는 `notice=REJECTED$` 로 쓴다.

### 5.7 도구

- **`phone_fake_peer.py`**: `send:reject:<정수>` — 그 수를 `msg` 로 실어 보낸다(범위를 검사하지 않는다 — 틀린 번호도 보낼 수 있어야 교환기를 시험한다). `expect:ended:reject:<정수>` — `msg` 가 그 수와 같아야 통과, `0` 은 "`msg` 가 없어야 한다". 번호를 쓰지 않으면 지금과 같다(`msg` 를 보지 않는다). `@<초>` 는 맨 뒤 그대로(`expect:ended:reject:2@15`). 번호는 `reject` 에만 붙일 수 있고 정수가 아니면 단계 오류다.
- **`phone_ctl.py`**: 고칠 코드가 없다 — 화면·상태·안내 이름 목록을 검사하는 곳이 없고(`parse_stat` 과 단계 문법은 이름과 무관), `STAT` 줄도 그대로다. 머리 주석의 "거절은 2번에 tap:876:428 …" 줄에 새 좌표(§5.4 표)를 덧붙인다. 그 위의 "예시" 단계 블록은 `test_documented_call_scenario_…` 가 글자대로 고정하므로 건드리지 않는다.
