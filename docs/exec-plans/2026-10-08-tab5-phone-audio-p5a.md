## 4. 전제·제약 (조사에서 확인한 것 — 2026-10-08, 출처는 §10)

- 코덱 음량 100 은 이미 DAC 0dB(레지스터 상한)다. 남은 아날로그 여유는 LOUT1 +4.5dB 뿐인데, **풀스케일에서 앰프가 이미 한계**다: 코덱 1Vrms × 앰프 약 3.5배 = 3.5Vrms 는 5V 전원과 1W 스피커를 넘는다(1W 는 약 −1.9dBFS = 꼭대기 약 26000). 앰프 이득 식은 2차 출처이고 기기에서 재지 않았다.
- 스피커 앰프와 에코 제거의 되먹임 칸은 코덱 출력(LOUT1)에서 갈라진다 → 디지털로 키우고 누르는 것은 에코 제거가 그대로 따라가지만, 앰프·스피커가 찌그러뜨린 소리는 되먹임 칸에 없어 지워지지 않는다. 그래서 받는 소리의 천장을 26000 으로 둔다.
- 두 대의 스피커폰이 동시 통화하는 검증된 공개 예제는 없다(xiaozhi·VideoLink·esp-skainet·esp-adf·esp-webrtc-solution 을 확인). "통화음 조정" 에이전트 스킬도 찾지 못했다. 가져온 것은 설계 원리다: 고전 스피커폰 IC(MC34118)의 음성 전환 감쇠 — 말하지 않는 쪽·대기 상태를 누르고, 푸는 것은 빨리(수십 ms) 누르는 것은 천천히(0.3~1초).
- 고리 모형(`tools/test_howl_loop.cpp`)의 메아리 감소 범위(작은 소리 10~25dB)는 여전히 **가정**이다. 모형은 방향과 상대 비교의 근거이지 기기의 소리를 보증하지 않는다.

2. 에코 제거를 `AEC_MODE_FD_LOW_COST` + `AEC_NLP_LEVEL_VERYAGGR` 로(esp-sr 공식 권장, xiaozhi 와 같은 조합): 남은 메아리가 줄고 CPU 도 준다(문서 수치 16.3% → 11.5%). 묶음이 32ms 라 구조를 바꿔야 하고 이 칩에서 돌려 본 적이 없다.
3. 잡음 억제 `ns_pro_create(10, …)`: 평탄화 앞에. 256 ↔ 160 표본 재배열과 CPU 측정이 필요하다.
4. 고음: `tilt` 대신 3kHz 근처만 +3dB(좁은 봉우리) — 고리 모형으로 먼저 본다.
5. Opus 32kbps(`opus 32` — 기기에서 써 본 적 없다). FEC 는 이 부품에서 효과가 없을 가능성이 크다(손실률을 걸지 않는다).
6. `esp_ae_howl`(주파수에서 찾아 노치) — 좁은 지속음용이라 이 울림에 듣는지 모른다.
